# Clause Registry — v2

Each entry records one stable EARS clause ID, its verbatim sentence, and its candidate-visible section anchor.

| Clause ID | Section anchor | Verbatim clause |
|---|---|---|
| `R4J-AOP-001` | `## Annotation Interception and Policy Resolution` / `**Annotation discovery.**` | “WHEN a proxied method or its target class carries a supported resilience annotation, THEN the corresponding aspect must intercept the invocation.” |
| `R4J-AOP-002` | `## Annotation Interception and Policy Resolution` / `**Annotation discovery.**` | “WHEN neither the method, target class, nor proxied interface exposes the matching annotation, THEN the aspect advice must invoke the join point exactly once without applying a resilience component.” |
| `R4J-AOP-003` | `## Annotation Interception and Policy Resolution` / `**Name and configuration selection.**` | “WHEN an annotation supplies `name`, THEN the aspect must resolve that value through the configured `SpelResolver` using the invoked method and arguments.” |
| `R4J-AOP-004` | `## Annotation Interception and Policy Resolution` / `**Name and configuration selection.**` | “WHEN an annotation supplies an empty `configuration`, THEN the aspect must use the resolved `name` as the registry configuration key.” |
| `R4J-AOP-005` | `## Annotation Interception and Policy Resolution` / `**Name and configuration selection.**` | “WHEN an annotation supplies a non-empty `configuration`, THEN the aspect must use that value as the registry configuration key while retaining the resolved `name` as the instance name.” |
| `R4J-AOP-006` | `## Annotation Interception and Policy Resolution` / `**Registry lookup.**` | “WHEN the selected registry contains the configuration key, THEN the aspect must create or retrieve the named component with that registered configuration.” |
| `R4J-AOP-007` | `## Annotation Interception and Policy Resolution` / `**Registry lookup.**` | “WHEN the selected registry lacks the configuration key, THEN the aspect must create or retrieve the named component with the registry default configuration.” |
| `R4J-AOP-008` | `## Annotation Interception and Policy Resolution` / `**Fallback boundary.**` | “WHEN annotation processing produces an invocation failure and `fallbackMethod` resolves to a compatible fallback, THEN the aspect must return the fallback projection instead of the failed primary projection.” |
| `R4J-EXE-001` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Synchronous and stage values.**` | “WHEN a Circuit Breaker, Rate Limiter, Retry, Bulkhead, or Timer aspect receives an ordinary synchronous return type, THEN the aspect must execute the join point through the corresponding checked-supplier policy.” |
| `R4J-EXE-002` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Synchronous and stage values.**` | “WHEN Circuit Breaker, Rate Limiter, Retry, Bulkhead, Timer, or Time Limiter advice receives a `CompletionStage` return type, THEN the aspect must preserve asynchronous completion while applying the corresponding policy to success and failure signals.” |
| `R4J-EXE-003` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Extension dispatch.**` | “WHERE an ordered aspect-extension list is present, the aspect must invoke the first extension whose `canHandleReturnType` accepts the declared return type.” |
| `R4J-EXE-004` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Extension dispatch.**` | “WHEN no registered extension accepts the return type, THEN Circuit Breaker, Rate Limiter, Retry, Bulkhead, and Timer advice must use their documented synchronous or `CompletionStage` fallback path.” |
| `R4J-EXE-005` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Time limits.**` | “IF Time Limiter advice receives neither `CompletionStage` nor a return type accepted by a registered extension, THEN the advice must raise `IllegalReturnTypeException`.” |
| `R4J-EXE-006` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Bulkhead modes.**` | “WHEN a Bulkhead annotation selects `Bulkhead.Type.SEMAPHORE`, THEN the aspect must execute ordinary values through `Bulkhead` and `CompletionStage` values through its asynchronous semaphore path.” |
| `R4J-EXE-007` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Bulkhead modes.**` | “WHEN a Bulkhead annotation selects `Bulkhead.Type.THREADPOOL` for a `CompletionStage`, THEN the aspect must execute through the named `ThreadPoolBulkhead` and return a completion-stage projection.” |
| `R4J-EXE-008` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Bulkhead modes.**` | “IF a thread-pool Bulkhead is applied to a non-`CompletionStage` return type, THEN the aspect must raise `IllegalStateException`.” |
| `R4J-EXE-009` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Bulkhead modes.**` | “IF a thread-pool Bulkhead rejects a `CompletionStage` invocation, THEN the aspect must return an exceptionally completed future whose failure is the rejection.” |
| `R4J-EXE-010` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Reactive adapters.**` | “WHERE Reactor is present, the Reactor extensions must preserve `Mono` and `Flux` shapes while applying Circuit Breaker, Rate Limiter, Retry, Bulkhead, Time Limiter, and Timer policies to their terminal signals.” |
| `R4J-EXE-011` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Reactive adapters.**` | “WHERE RxJava 2 is present, the RxJava 2 extensions must preserve supported reactive shapes while applying the selected policy to their terminal signals.” |
| `R4J-EXE-012` | `## Synchronous, Asynchronous, and Reactive Execution` / `**Reactive adapters.**` | “WHERE RxJava 3 is present, the RxJava 3 extensions must preserve supported reactive shapes while applying the selected policy to their terminal signals.” |
| `R4J-FAL-001` | `## Fallback Selection and Projection` / `**Fallback lookup.**` | “WHEN `fallbackMethod` is empty or resolves to no compatible method, THEN `FallbackExecutor.execute` must invoke the primary function.” |
| `R4J-FAL-002` | `## Fallback Selection and Projection` / `**Fallback lookup.**` | “WHEN `fallbackMethod` resolves to a simple method name, THEN fallback lookup must target the proxied service and accept either the original parameter list followed by a `Throwable` subtype or a single `Throwable` subtype parameter.” |
| `R4J-FAL-003` | `## Fallback Selection and Projection` / `**Fallback lookup.**` | “WHEN `fallbackMethod` resolves to `beanName::methodName`, THEN fallback lookup must target that Spring bean and the named method.” |
| `R4J-FAL-004` | `## Fallback Selection and Projection` / `**Fallback lookup.**` | “IF `FallbackMethod.create` finds no method with a compatible name, parameter contract, and assignable return type, THEN it must raise `NoSuchMethodException`.” |
| `R4J-FAL-005` | `## Fallback Selection and Projection` / `**Exception specificity.**` | “WHEN multiple compatible fallback overloads exist, THEN `FallbackMethod.fallback` must select the overload whose final exception parameter is nearest to the thrown exception in its superclass chain.” |
| `R4J-FAL-006` | `## Fallback Selection and Projection` / `**Exception specificity.**` | “WHEN the available fallback overloads do not accept the thrown exception, THEN `FallbackMethod.fallback` must rethrow the original exception.” |

| `R4J-FAL-010` | `## Fallback Selection and Projection` / `**Async and reactive fallback.**` | “WHEN a `CompletionStage` primary completes exceptionally, THEN `CompletionStageFallbackDecorator` must complete its returned stage with the fallback value or the resulting fallback failure.” |
| `R4J-FAL-011` | `## Fallback Selection and Projection` / `**Async and reactive fallback.**` | “WHERE Reactor or RxJava fallback decorators support the declared return type, the decorator must recover terminal errors without changing the reactive family.” |
| `R4J-CFG-001` | `## Configuration, Registries, and Aspect Order` / `**Registry construction.**` | “WHEN a Spring configuration class creates a component registry, THEN it must apply named configurations, registry event consumers, event-consumer buffers, tags, and matching customizers supplied through the corresponding configuration properties.” |
