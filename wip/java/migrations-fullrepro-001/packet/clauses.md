This internal sidecar maps stable clause IDs to verbatim candidate-visible specification sentences. Representative Workflows are orientation only. Every mapped rule passed the upstream-documentation ceiling, 1:N support, and rule-not-instance parts of Q3.

## Repository and Environment Configuration

- **MIG-CONF-001** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “When `migrate init` targets an absent or empty base directory, the command must create the base directory, `drivers`, `environments`, and `scripts`, then create a README, `environments/development.properties`, `scripts/bootstrap.sql`, the changelog-creation migration, and a first migration template.”
- **MIG-CONF-002** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “If the initialization target contains any non-hidden entry, then `migrate init` must fail without replacing that entry.”
- **MIG-CONF-003** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “The `--path` option must select the repository base directory and must default to the current working directory.”
- **MIG-CONF-004** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “The `--env` option must select `environments/<environment>.properties` and must default to `development`.”
- **MIG-CONF-005** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “The `--envpath`, `--scriptpath`, `--driverpath`, and `--hookpath` options must replace the corresponding derived repository directories when explicitly present.”
- **MIG-CONF-006** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “If a database command targets a base path that is absent or is not a directory, then the command must report the invalid path and must not run the operation.”
- **MIG-CONF-007** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “The environment file must support `time_zone`, `script_char_set`, `driver`, `url`, `username`, `password`, `changelog`, `auto_commit`, `delimiter`, `full_line_delimiter`, `send_full_script`, `remove_crs`, `ignore_warnings`, `driver_path`, and the hook keys described below.”
- **MIG-CONF-008** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “The environment must default `time_zone` to `GMT+0:00`, `script_char_set` to the platform default charset, `changelog` to `CHANGELOG`, `delimiter` to `;`, and `ignore_warnings` to `true`; its remaining boolean settings must default to `false`.”
- **MIG-CONF-009** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “Where a process environment variable named `MIGRATIONS_<KEY>` is present, the environment must replace the same lower-case file property with that value.”
- **MIG-CONF-010** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “Where a Java system property named `MIGRATIONS_<KEY>` is present, the environment must replace both the file property and the process-environment value for that key.”
- **MIG-CONF-011** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “The environment must expose non-setting properties through `getVariables()` for `${name}` substitution in scripts and templates.”
- **MIG-CONF-012** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “An `Environment` constructed with `file` must expose the resolved settings through `getTimeZone()`, `getDelimiter()`, `getScriptCharset()`, `isFullLineDelimiter()`, `isSendFullScript()`, `isAutoCommit()`, `isRemoveCrs()`, `isIgnoreWarnings()`, `getDriverPath()`, `getDriver()`, `getUrl()`, `getUsername()`, `getPassword()`, all fourteen named hook getters, and `getVariables()`.”
- **MIG-CONF-013** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “If the selected environment file is absent or unreadable, then environment construction must raise `MigrationException`.”
- **MIG-CONF-014** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “When `send_full_script` is `true`, a database operation must send the selected script as one JDBC statement; when it is `false`, the operation must split commands according to `delimiter` and `full_line_delimiter`.”
- **MIG-CONF-015** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “When `full_line_delimiter` is `false`, the delimiter must terminate a command at the end of a line; when it is `true`, a line containing only the delimiter must terminate the command.”
- **MIG-CONF-016** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “When `auto_commit` is `false`, successful script execution must commit as an operation unit and a failed statement must roll back the active unit; when it is `true`, statements must use JDBC auto-commit.”
- **MIG-CONF-017** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “When `ignore_warnings` is `false`, a JDBC warning must fail the operation; when it is `true`, warnings must not interrupt it.”
- **MIG-CONF-018** — [Repository and Environment Configuration](spec.md#repository-and-environment-configuration) — “If a selected script ends with an unterminated command while line-by-line execution is active, then execution must raise `MigrationException`.”
## Migration Files and Loaders

- **MIG-LOAD-001** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “A required `FileMigrationLoader` construction form must accept, in order, `scriptsDir` as a `java.io.File`, `charset` as a nullable charset-name `String`, and `variables` as `java.util.Properties`.”
- **MIG-LOAD-020** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “When `charset` is non-null, the file loader must resolve that name as the reader charset.”
- **MIG-LOAD-021** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “When `charset` is `null`, the file loader must read scripts with the platform default charset.”
- **MIG-LOAD-002** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “A filesystem migration name must have a numeric ID prefix, an underscore-separated description, and the `.sql` suffix; the loader must expose the numeric prefix as `Change.id`, spaces in place of description underscores, and the original name as `Change.filename`.”
- **MIG-LOAD-003** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “The file loader must sort migration names in ascending filename order and must omit non-SQL files, `bootstrap.sql`, and `onabort.sql` from `getMigrations()`.”
- **MIG-LOAD-004** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “When `getScriptReader(change, false)` is requested, the loader must return the script content above the `-- //@UNDO` marker; when `getScriptReader(change, true)` is requested, it must return the content below that marker.”
- **MIG-LOAD-005** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “When a selected script contains `${name}` and the loader properties define `name`, the returned reader must replace the token in both DO and UNDO sections.”
- **MIG-LOAD-006** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “If a migration filename does not contain a valid numeric prefix, then the file loader must raise `MigrationException` when discovering it.”
- **MIG-LOAD-007** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “The file loader must return a reader for existing `bootstrap.sql` or `onabort.sql` and must return `null` when the requested special script is absent.”
- **MIG-LOAD-008** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “When `migrate new <description>` runs without `--idpattern`, the command must create a timestamp-prefixed `.sql` file whose remaining name replaces description spaces with underscores.”
- **MIG-LOAD-009** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “Where `--idpattern` or the `idpattern` global property is present, `init` and `new` must generate the next numeric ID formatted by that decimal pattern.”
- **MIG-LOAD-010** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “The generated migration must contain the description, a forward section, and the `-- //@UNDO` boundary followed by a reverse section.”
- **MIG-LOAD-011** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “Where `--template=<path>` is present, `new` must use that external template and replace `${description}` with the supplied description.”
- **MIG-LOAD-012** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “Where `new_command.template` is configured and `--template` is absent, `new` must resolve that template relative to `MIGRATIONS_HOME`.”
- **MIG-LOAD-013** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “If no description is supplied, the selected environment is unavailable, or an explicitly selected template cannot be read, then `new` must raise `MigrationException` without creating a completed migration file.”
- **MIG-LOAD-014** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “A `MigrationScript` implementation must return a unique `BigDecimal` ID, a short description, forward SQL from `getUpScript()`, and reverse SQL from `getDownScript()`.”
- **MIG-LOAD-015** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “A `JavaMigrationLoader` must discover concrete `MigrationScript` implementations in its `packageNames`, instantiate them, expose their class names as `Change.filename`, and return changes ordered by numeric ID to consuming operations.”
- **MIG-LOAD-016** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “When a Java loader is constructed with `classLoader`, discovery must use that loader; otherwise it must use the ordinary application classpath.”
- **MIG-LOAD-017** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “A Java loader must return the selected class's forward or reverse SQL from `getScriptReader`, a sole `BootstrapScript` from `getBootstrapReader`, and a sole `OnAbortScript` from `getOnAbortReader`.”
- **MIG-LOAD-018** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “If more than one implementation exists for a requested `BootstrapScript` or `OnAbortScript`, or a selected script class cannot be instantiated, then the Java loader must raise `MigrationException`.”
- **MIG-LOAD-019** — [Migration Files and Loaders](spec.md#migration-files-and-loaders) — “A custom `FileMigrationLoaderFactory` must be discoverable through `/META-INF/services/org.apache.ibatis.migration.FileMigrationLoaderFactory` and must return a `MigrationLoader` from the selected paths and environment.”
## Schema Lifecycle Operations

- **MIG-LIFE-001** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When `up` runs without a step count, it must apply every migration whose ID is greater than the latest applied changelog ID, in ascending ID order.”
- **MIG-LIFE-002** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “Where a positive step count is present, `up` must stop after that many eligible migrations.”
- **MIG-LIFE-003** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “For every successfully applied migration, `up` must execute its forward SQL and insert its ID, application timestamp, and description into the changelog.”
- **MIG-LIFE-004** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “If the `UpOperation` step count is less than one, then construction must raise `IllegalArgumentException`.”
- **MIG-LIFE-005** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When an up operation fails and the loader returns an on-abort reader, the operation must execute the on-abort SQL before raising `MigrationException`.”
- **MIG-LIFE-006** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When `down` runs without a step count, it must execute the reverse SQL of the latest applied migration and remove that migration from the changelog.”
- **MIG-LIFE-007** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “Where a step count is present, `down` must repeat that behavior from newest to oldest until the count is reached or removing the changelog prevents further undo.”
- **MIG-LIFE-008** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When `redo` runs without a step count, it must perform one down step followed by one up step; where a count is present, it must use that count for both directions.”
- **MIG-LIFE-009** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “A completed redo must leave the same set of applied migration IDs while re-executing both reverse and forward SQL for the selected tail.”
- **MIG-LIFE-010** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When `version <id>` names a repository migration above the current version, the operation must apply eligible migrations through that ID inclusively.”
- **MIG-LIFE-011** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When `version <id>` names a repository migration below the current version, the operation must undo applied migrations above that ID and must leave the named version applied.”
- **MIG-LIFE-012** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When the database is already at the requested version, the version operation must leave schema and changelog state unchanged.”
- **MIG-LIFE-013** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “If the requested version is absent from the loader's migration set, then `VersionOperation` must raise `MigrationException`.”
- **MIG-LIFE-014** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When `pending` runs, it must apply every repository migration missing from the changelog in ascending ID order, including migrations whose IDs are below an already applied migration.”
- **MIG-LIFE-015** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “If the changelog table does not exist, then `pending` must raise `MigrationException` and must direct no migration SQL to the database.”
- **MIG-LIFE-016** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When `bootstrap` runs before the changelog exists and the loader supplies a bootstrap reader, it must execute that SQL without inserting a changelog row.”
- **MIG-LIFE-017** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When the changelog exists and force is `false`, bootstrap must leave database state unchanged.”
- **MIG-LIFE-018** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “Where force is `true`, bootstrap must execute the available bootstrap SQL even when the changelog exists.”
- **MIG-LIFE-019** — [Schema Lifecycle Operations](spec.md#schema-lifecycle-operations) — “When no bootstrap script exists, the bootstrap operation must return without applying SQL and must report the missing script through its output stream.”
## Status and Offline Script Projections

- **MIG-VIEW-001** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “When status runs without a changelog table, it must return every discovered repository migration as pending.”
- **MIG-VIEW-002** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “When status runs with a changelog table, it must combine repository migrations and changelog rows by numeric ID, marking repository-only changes pending, shared changes applied, and changelog-only changes missing.”
- **MIG-VIEW-003** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “`StatusOperation` must expose the combined ordered list through `getCurrentStatus()` and matching totals through `getAppliedCount()`, `getPendingCount()`, and `getMissingCount()`.”
- **MIG-VIEW-004** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “The `status` command must print each combined change in ascending ID order, including its ID, applied timestamp or pending state, and description.”
- **MIG-VIEW-005** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “When `script <lower> <upper>` has `lower < upper`, it must emit the forward sections with IDs greater than `lower` and less than or equal to `upper`, in ascending order.”
- **MIG-VIEW-006** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “When `script <upper> <lower>` has the first version greater than the second, it must emit the reverse sections over the same exclusive/inclusive boundary in descending rollback order.”
- **MIG-VIEW-007** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “When the lower boundary is `0`, forward generation must include the first migration; when the destination is `0`, reverse generation must include the first migration's undo section.”
- **MIG-VIEW-008** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “When `script pending` runs, it must emit forward SQL for the pending tail after the last applied migration; when `script pending_undo` runs, it must emit the corresponding reverse SQL.”
- **MIG-VIEW-009** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “If the two explicit script versions are equal, absent from the repository, nonnumeric, or supplied with an invalid argument count, then the command must fail without emitting a completed delta.”
- **MIG-VIEW-010** — [Status and Offline Script Projections](spec.md#status-and-offline-script-projections) — “Script generation must write SQL to standard output and must not update the schema or changelog.”
## Migration Hooks

- **MIG-HOOK-001** — [Migration Hooks](spec.md#migration-hooks) — “The environment must recognize `hook_before_up`, `hook_before_each_up`, `hook_after_each_up`, `hook_after_up`, the corresponding four `down` keys, `hook_before_new`, `hook_after_new`, and the corresponding four `script` keys.”
- **MIG-HOOK-002** — [Migration Hooks](spec.md#migration-hooks) — “A hook value must contain a language and filename separated by `:`, followed by zero or more `name=value` bindings.”
- **MIG-HOOK-003** — [Migration Hooks](spec.md#migration-hooks) — “Up, down, and pending operations with eligible changes must invoke `before` once, `beforeEach` and `afterEach` around every selected migration, and `after` once, in that order.”
- **MIG-HOOK-004** — [Migration Hooks](spec.md#migration-hooks) — “When an up or down operation selects no migration, its operation hooks must not execute.”
- **MIG-HOOK-005** — [Migration Hooks](spec.md#migration-hooks) — “New hooks must run before and after file creation with a `NewHookContext`; script hooks must surround delta generation with a `ScriptHookContext` describing the selected change and direction.”
- **MIG-HOOK-006** — [Migration Hooks](spec.md#migration-hooks) — “If a before-new hook raises, then the new command must fail before creating the migration file.”
- **MIG-HOOK-007** — [Migration Hooks](spec.md#migration-hooks) — “Every hook binding map must expose its context under `MigrationHook.HOOK_CONTEXT`, whose value is the string `hookContext`.”
- **MIG-HOOK-008** — [Migration Hooks](spec.md#migration-hooks) — “An operation-level `HookContext` must expose a `null` change, while each-change hooks must expose a defensive `Change` copy through `getChange()`.”
- **MIG-HOOK-009** — [Migration Hooks](spec.md#migration-hooks) — “`HookContext.getConnection()` must return a new caller-closeable JDBC connection, and `executeSql(Reader)` and `executeSql(String)` must execute SQL through the active operation runner.”
- **MIG-HOOK-010** — [Migration Hooks](spec.md#migration-hooks) — “`NewHookContext` must return the supplied description and generated filename; before-new observes the name before the file exists.”
- **MIG-HOOK-011** — [Migration Hooks](spec.md#migration-hooks) — “`ScriptHookContext` must return the selected `Change` and must expose whether the projection is an undo through `isUndo()`.”
- **MIG-HOOK-012** — [Migration Hooks](spec.md#migration-hooks) — “Hook scripts must receive repository paths as `migrationPaths`, environment variables as global bindings, and explicitly configured bindings as overrides for the selected hook.”
- **MIG-HOOK-013** — [Migration Hooks](spec.md#migration-hooks) — “Where `_function` and repeated `_arg` bindings are present for a JSR-223 hook, the hook must invoke the named top-level function with those arguments.”
- **MIG-HOOK-014** — [Migration Hooks](spec.md#migration-hooks) — “Where `_object`, `_method`, and repeated `_arg` bindings are present for a JSR-223 hook, the hook must invoke the named object's method with those arguments.”
- **MIG-HOOK-015** — [Migration Hooks](spec.md#migration-hooks) — “If a configured hook language, file, function, object, or method cannot be resolved or executed, then the enclosing command or operation must raise `MigrationException`.”
- **MIG-HOOK-016** — [Migration Hooks](spec.md#migration-hooks) — “`MigrationHook` must define callbacks named `before`, `beforeEach`, `afterEach`, and `after`.”
- **MIG-HOOK-017** — [Migration Hooks](spec.md#migration-hooks) — “Each `MigrationHook` callback must accept a `java.util.Map<String,Object>` bindings map and must return no value.”
- **MIG-HOOK-018** — [Migration Hooks](spec.md#migration-hooks) — “The `before` and `after` callbacks must receive an operation-level `HookContext` under `MigrationHook.HOOK_CONTEXT`, while `beforeEach` and `afterEach` must receive a defensive per-change `HookContext` under that key.”
## Programmatic Runtime API

- **MIG-JAVA-001** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “A `SelectedPaths` instance must default `basePath` to the current directory and must derive `envPath`, `scriptPath`, `driverPath`, and `hookPath` as `environments`, `scripts`, `drivers`, and `hooks` beneath it until `setBasePath()`, `setEnvPath()`, `setScriptPath()`, `setDriverPath()`, or `setHookPath()` supplies an override returned by its matching getter.”
- **MIG-JAVA-002** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`ConnectionProvider.getConnection()` must return the JDBC connection used by an operation and must propagate `SQLException` from acquisition.”
- **MIG-JAVA-003** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “A `DataSourceConnectionProvider` must obtain each requested connection from its constructor-supplied `DataSource`.”
- **MIG-JAVA-004** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “A `JdbcConnectionProvider` must load and register its constructor-supplied driver class, then obtain connections from `DriverManager` using `url`, `username`, and `password`; its overload with `classLoader` must load the driver through that loader.”
- **MIG-JAVA-005** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “If a JDBC driver class cannot be loaded or instantiated, then `JdbcConnectionProvider` construction must raise `IllegalStateException`.”
- **MIG-JAVA-006** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “A `DatabaseOperationOption` must default to changelog table `CHANGELOG`, stop-on-error enabled, warning failure enabled, auto-commit disabled, send-full-script disabled, CR removal disabled, escape processing enabled, full-line delimiter disabled, and delimiter `;`.”
- **MIG-JAVA-007** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “The `DatabaseOperationOption` pairs `getChangelogTable()`/`setChangelogTable()`, `isStopOnError()`/`setStopOnError()`, `isThrowWarning()`/`setThrowWarning()`, `isAutoCommit()`/`setAutoCommit()`, `isSendFullScript()`/`setSendFullScript()`, `isRemoveCRs()`/`setRemoveCRs()`, `isEscapeProcessing()`/`setEscapeProcessing()`, `isFullLineDelimiter()`/`setFullLineDelimiter()`, and `getDelimiter()`/`setDelimiter()` must expose the active values; a `null` option supplied to a lifecycle `operate` method must select the defaults.”
- **MIG-JAVA-008** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`Change` must expose mutable properties through `getId()`/`setId()`, `getDescription()`/`setDescription()`, `getAppliedTimestamp()`/`setAppliedTimestamp()`, and `getFilename()`/`setFilename()`, and its copy constructor must copy all four values.”
- **MIG-JAVA-009** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`Environment.CHANGELOG` must equal the string `changelog` used as the public variable key for changelog-table selection.”
- **MIG-JAVA-010** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`Change` equality, hashing, and natural ordering must use the numeric ID so loaders and changelog views match changes independently of description, timestamp, and filename.”
- **MIG-JAVA-011** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “Every lifecycle `operate` method must return the same operation instance after successful completion and must close the connection acquired from its provider.”
- **MIG-JAVA-012** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “Where a non-null `PrintStream` is supplied, operations must report their user-facing progress to it; where it is `null`, operations must complete without requiring output.”
- **MIG-JAVA-013** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “If connection, loader, script, or changelog work fails during a lifecycle operation, then the operation must raise `MigrationException` with the underlying cause retained.”
- **MIG-JAVA-014** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`Change` must support construction from a `BigDecimal` `id` alone, and `getId()` must immediately return that value.”
- **MIG-JAVA-015** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`Change` must support construction from a `BigDecimal` `id`, followed by a `String` `appliedTimestamp`, followed by a `String` `description`, and the matching getters must immediately return those values.”
- **MIG-JAVA-016** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`UpOperation` and `DownOperation` must each provide a hook-aware `operate` form whose arguments are, in order, a `ConnectionProvider`, a `MigrationLoader`, a `DatabaseOperationOption`, a `PrintStream`, and a `MigrationHook`.”
- **MIG-JAVA-017** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “When a hook-aware `operate` form completes successfully, it must return the same operation instance and must apply the documented before, per-change, and after callback ordering.”
- **MIG-JAVA-018** — [Programmatic Runtime API](spec.md#programmatic-runtime-api) — “`UpOperation` and `DownOperation` must each provide a four-argument no-explicit-hook form with the same first four collaborators in the same order.”

- **MIG-ERR-008** — [Error Semantics](spec.md#error-semantics) — “If the driver cannot be loaded or instantiated, then `JdbcConnectionProvider` must raise `IllegalStateException`.”
- **MIG-ERR-009** — [Error Semantics](spec.md#error-semantics) — “If a lifecycle operation cannot complete database work, then it must raise `MigrationException` and retain the cause.”
- **MIG-ERR-010** — [Error Semantics](spec.md#error-semantics) — “If a configured hook cannot be resolved or executed, then the enclosing workflow must raise `MigrationException`.”
- **MIG-ERR-011** — [Error Semantics](spec.md#error-semantics) — “If command execution fails, then the Java runner must terminate with status `1`; successful commands and help must return status `0`.”
## Cross-View Invariants

- **MIG-INV-001** — [Cross-View Invariants](spec.md#cross-view-invariants) — “A migration applied through `migrate up` or `UpOperation.operate()` must produce the same schema effect and changelog identity for the same loader and operation options.”
- **MIG-INV-002** — [Cross-View Invariants](spec.md#cross-view-invariants) — “A migration present in the changelog must appear as applied in `StatusOperation` and CLI status, while a repository-only migration must appear as pending in both projections.”
- **MIG-INV-003** — [Cross-View Invariants](spec.md#cross-view-invariants) — “A successful down operation must remove the selected changelog row, update status to pending for a still-present repository migration, and execute the same UNDO section emitted by the corresponding reverse script projection.”
- **MIG-INV-004** — [Cross-View Invariants](spec.md#cross-view-invariants) — “An offline forward delta and an online up operation over the same ID interval must select the same migration IDs in the same order.”
- **MIG-INV-005** — [Cross-View Invariants](spec.md#cross-view-invariants) — “Filesystem and Java loaders exposing equal numeric IDs must produce equal `Change` identities and the same lifecycle ordering.”
- **MIG-INV-006** — [Cross-View Invariants](spec.md#cross-view-invariants) — “A hook's each-change `Change` value must match the migration currently reported to the operation stream and inserted into or removed from the changelog.”
- **MIG-INV-007** — [Cross-View Invariants](spec.md#cross-view-invariants) — “Environment and `DatabaseOperationOption` settings for changelog name, delimiter, transactions, full-script mode, CR handling, and warnings must affect CLI and runtime operations consistently.”
- **MIG-INV-008** — [Cross-View Invariants](spec.md#cross-view-invariants) — “A completed redo must preserve the status set of applied IDs while producing both the down and up schema effects for its selected tail.”
