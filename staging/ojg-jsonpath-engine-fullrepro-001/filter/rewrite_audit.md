# Rewrite audit — ojg-jsonpath-engine-fullrepro-001 (Track A, Step 1)

Upstream test suite for the `jp` package at v1.28.5
(commit fc5d690db5103e00c48f56b37544bd22ba0d77b9), 19 files, 159 test
functions. 18 files are external black-box (`package jp_test`), but every
substantive file imports out-of-scope packages of the same module: the
`tt` assert layer in all of them, and `oj`/`sen`/`pretty` (expected values

`github.com/ohler55/ojg`, so an oracle test importing any sibling package
cannot compile against a spec-following delivery. A valid rewrite would
have to (a) replace the assert layer, (b) convert
serialization-golden comparisons into value comparisons — changing what
the tests verify, and (c) drop the gen/alt variants entangled in the
shared mega-tables; per the rewrite criterion this is a discard, not a
rewrite.

## Shared-helper contract audit

The oracle uses one in-oracle support file per suite
(`oracle/atomic/support_test.go`, `oracle/integration/support_test.go`)
providing only: document constructors returning plain Go literals
(`map[string]any`, `[]any`), small comparison helpers built on
`t.Helper`/`t.Fatalf` (deep equality via `reflect.DeepEqual`,
order-insensitive comparison by sorting rendered forms where the spec
leaves order unspecified), and exact-text error/panic assertions. Every
convention they rely on is stated in the spec: the data model and
traversal rules (section Selecting Values from Data), unspecified-order
comparisons (sections Selecting Values from Data; Walking, Locating, and
Path Matching; Appendix B), and the exact error texts (section Error
Semantics). No environment variables, no file layout conventions, no CLI
flags, no fixture files.
