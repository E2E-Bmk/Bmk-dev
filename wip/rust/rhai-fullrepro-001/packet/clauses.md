# Clause Sidecar — rhai-fullrepro-001

Each clause ID maps to a verbatim candidate-visible sentence and section anchor.

| Clause ID | Section | Clause |
|---|---|---|
| RHAI-EVAL-001 | Script Evaluation And Compilation | The `Engine::new` constructor must create an engine with the standard packages, language features, limits, module resolver, callbacks, and optimization behavior enabled for the active Cargo feature set. |
| RHAI-EVAL-002 | Script Evaluation And Compilation | The `Engine::new_raw` constructor must create an engine without the standard package registrations. |
| RHAI-EVAL-003 | Script Evaluation And Compilation | The free functions `rhai::eval` and `rhai::run` must create a fresh `Engine` and evaluate the supplied script through the matching engine method. |
| RHAI-EVAL-004 | Script Evaluation And Compilation | When `eval` receives script text, the engine must execute the script in a fresh `Scope` and return the final expression converted to the requested Rust type. |
| RHAI-EVAL-005 | Script Evaluation And Compilation | When `eval_with_scope` receives script text and a mutable `Scope`, the engine must compile against that scope, execute against the same scope, and leave mutations to visible scope variables in that scope. |
| RHAI-EVAL-006 | Script Evaluation And Compilation | When `run` or `run_with_scope` receives script text, the engine must execute it for side effects and return unit on success. |
| RHAI-EVAL-007 | Script Evaluation And Compilation | If the script contains invalid syntax, then text-based evaluation and run calls must return boxed `EvalAltResult::ErrorParsing`; if runtime execution fails, then they must return boxed `EvalAltResult`; if the final value does not convert to the requested Rust type, then they must return `EvalAltResult::ErrorMismatchOutputType`. |
| RHAI-EVAL-008 | Script Evaluation And Compilation | When `eval_expression` or `eval_expression_with_scope` receives script text, the engine must parse it as one global expression rather than as a full statement script. |
| RHAI-EVAL-009 | Script Evaluation And Compilation | If the input is not a valid expression, then these methods must return boxed `EvalAltResult::ErrorParsing`; if the expression result does not convert to the requested Rust type, then they must return `EvalAltResult::ErrorMismatchOutputType`. |
| RHAI-COMP-001 | Script Evaluation And Compilation | When `compile` receives script text, the engine must return an `AST` that represents the script and is reusable for later `eval_ast`, `eval_ast_with_scope`, `run_ast`, `run_ast_with_scope`, and `call_fn` calls. |
| RHAI-COMP-002 | Script Evaluation And Compilation | When `compile_expression` receives script text, the engine must return an `AST` containing an expression. |
| RHAI-COMP-003 | Script Evaluation And Compilation | When `compile_with_scope`, `compile_expression_with_scope`, or `compile_scripts_with_scope` receives a scope, the engine must use constant entries in that scope for constant propagation when optimization is enabled. |
| RHAI-COMP-004 | Script Evaluation And Compilation | When `compile_scripts_with_scope` receives multiple script segments, the engine must concatenate the segments in order without inserting separators and compile the combined stream. |
| RHAI-COMP-005 | Script Evaluation And Compilation | When `compile_into_self_contained` receives a scope and script text, the engine must compile the script and eagerly resolve literal-string imports through the current `ModuleResolver`, recursively embedding resolved modules into the resulting `AST`. |
| RHAI-FILE-001 | Script Evaluation And Compilation | When `compile_file`, `eval_file`, or `run_file` receives a path, the engine must read the file as UTF-8 script text, remove a leading shebang line, set the `AST` source to the path for compiled-file calls, and then use the same parsing and execution behavior as text-based methods. |
| RHAI-FILE-002 | Script Evaluation And Compilation | When the file cannot be opened or read, these methods must return `EvalAltResult::ErrorSystem`. |
| RHAI-SCOPE-001 | Scope And Values | `Scope::new` must create an empty scope, and `Scope::with_capacity` must create an empty scope with storage prepared for the requested number of entries. |
| RHAI-SCOPE-002 | Scope And Values | When `push` receives a name and clonable Rust value, the scope must append a read-write variable. |
| RHAI-SCOPE-003 | Scope And Values | When `push_constant` or `push_constant_dynamic` receives a name and value, the scope must append a read-only variable. |
| RHAI-SCOPE-004 | Scope And Values | If a later entry reuses an earlier name, then lookup must treat the later entry as the visible one while preserving the earlier shadowed entry. |
| RHAI-SCOPE-005 | Scope And Values | When `pop` is called on a non-empty scope, the scope must remove the last entry. |
| RHAI-SCOPE-006 | Scope And Values | If `pop` is called on an empty scope, then it must panic. |
| RHAI-SCOPE-007 | Scope And Values | `get_value`, `get_value_ref`, `get_value_mut`, `get`, and `get_mut` must search from the last entry backward. |
| RHAI-SCOPE-008 | Scope And Values | When `set_or_push` receives a name and value, the scope must update the visible read-write entry if one exists; otherwise it must append a new read-write entry. |
| RHAI-SCOPE-009 | Scope And Values | When `set_value` receives a name and value, the scope must update the visible read-write entry, append a new entry if the name is absent, and panic if the visible entry is constant. |
| RHAI-SCOPE-010 | Scope And Values | `clone_visible` must return a scope containing only the visible instance of each name and must preserve each retained entry's access mode and aliases. |
| RHAI-NATIVE-001 | Native Functions And Script Function Calls | When `register_fn` receives a script-visible name and a Rust function or closure, the engine must register it in the global namespace, assume it is pure except for property and index setters, and make it available to scripts by name with overload resolution based on name, arity, argument types, and receiver type. |
| RHAI-NATIVE-002 | Native Functions And Script Function Calls | When `register_raw_fn` receives a name, argument `TypeId` list, and callback, the engine must call the callback with `NativeCallContext` and mutable `Dynamic` arguments after argument types have matched the supplied list. |
| RHAI-NATIVE-003 | Native Functions And Script Function Calls | When `register_type` receives a Rust type, the engine must make the type usable as a Rhai custom type and use Rust's type name for `type_of`. |
| RHAI-NATIVE-004 | Native Functions And Script Function Calls | When `register_type_with_name` receives a Rust type and display name, the engine must use that display name for script-visible type naming. |
| RHAI-CALL-001 | Native Functions And Script Function Calls | When `call_fn` receives a scope, `AST`, function name, and arguments, the engine must evaluate the `AST` first to load required modules and declarations, call the script-defined function matching the name and arity, rewind temporary declarations after the call, and convert the return value to the requested Rust type. |
| RHAI-CALL-002 | Native Functions And Script Function Calls | When `call_fn_with_options` receives `CallFnOptions`, `bind_this_ptr` must bind the provided `Dynamic` as `this`, `with_tag` must provide run-local custom state overriding the engine default tag, `eval_ast(false)` must skip pre-call AST evaluation, `rewind_scope(false)` must preserve variables declared while evaluating or calling, and `in_all_namespaces(true)` must search registered native and module namespaces as well as the script functions in the `AST`. |
| RHAI-MOD-001 | Modules And Module Resolution | `Module::new` must create an indexed empty module. |
| RHAI-MOD-002 | Modules And Module Resolution | `set_var` must store a `Dynamic` value under a name, `contains_var` must report whether that name exists, `get_var` must return a cloned `Dynamic`, and `get_var_value` must return the value converted to the requested Rust type or `None` when absent or not convertible. |
| RHAI-MOD-003 | Modules And Module Resolution | When `set_native_fn` receives a name and Rust function, the module must store it in the internal namespace, replace an existing function with the same public call key, and return the native function hash. |
| RHAI-MOD-004 | Modules And Module Resolution | When `set_sub_module` receives a name and shared module, the module must make the submodule reachable under that name. |
| RHAI-MOD-005 | Modules And Module Resolution | `build_index` must prepare variables, functions, and submodules for namespace-qualified access and return the module for chaining. |
| RHAI-MOD-006 | Modules And Module Resolution | When `register_global_module` receives a shared module, the engine must expose that module's functions and type iterators without namespace qualification, ignore its submodules and variables for global registration, and prefer modules registered later during global function search. |
| RHAI-MOD-007 | Modules And Module Resolution | When `register_static_module` receives a path and shared module, the engine must expose the module under that namespace path while also exposing functions marked for the global namespace without qualification. |
| RHAI-RES-001 | Modules And Module Resolution | `DummyModuleResolver::new` must create a resolver whose `resolve` always returns `EvalAltResult::ErrorModuleNotFound`. |
| RHAI-RES-002 | Modules And Module Resolution | `StaticModuleResolver::new` must create an empty resolver; `insert` must store an indexed module under a path and assign the path as ID when the module has no ID; `remove`, `contains_path`, `iter`, `iter_mut`, `paths`, `values`, `clear`, `is_empty`, `len`, and `merge` must project that path-to-module map. |
| RHAI-GRAIN-001 | Grain Bytecode Programs | `Compiler::new` must create a default compiler. |
| RHAI-GRAIN-002 | Grain Bytecode Programs | When `Compiler::compile` receives an `AST`, it must return a `Program` that owns or references everything needed to execute the script except the `Engine`. |
| RHAI-GRAIN-003 | Grain Bytecode Programs | For every script accepted by `Engine::compile`, evaluating the compiled `Program` with `Vm::eval_with_scope` must return the same success value or public `EvalAltResult` variant family as `Engine::eval_ast_with_scope`, and it must leave the caller's `Scope` with the same visible variables, values, and constant flags. |
| RHAI-GRAIN-004 | Grain Bytecode Programs | When the compiler cannot lower a construct to bytecode, the `Program` must retain a residual AST fragment and `residual_count` or `residual_nodes` must report remaining walker-backed work. |
| RHAI-GRAIN-005 | Grain Bytecode Programs | Residual fragments must preserve runtime behavior through `Vm`, but they must prevent artifact writing. |
| RHAI-GRAIN-006 | Grain Bytecode Programs | When `residual_count` is zero, `write` must serialize a program to bytes that `Program::read` accepts in the same ABI and hashing environment. |
| RHAI-GRAIN-007 | Grain Bytecode Programs | When residual fragments remain, `write` must return `WriteError::HasResiduals`. |
| RHAI-GRAIN-008 | Grain Bytecode Programs | `Vm::new` must bind a VM to an `Engine` and reuse runtime caches across calls on that VM. |
| RHAI-GRAIN-009 | Grain Bytecode Programs | `Vm::eval`, `eval_with_scope`, `run`, and `run_with_scope` must execute a `Program` with a fresh or provided scope following the same result and scope mutation rules as engine AST evaluation. |
| RHAI-ERR-001 | Error Semantics | If arithmetic evaluation fails because an operation such as division, remainder, exponentiation, shift, or numeric conversion cannot produce a valid result, then it must return `EvalAltResult::ErrorArithmetic`. |
| RHAI-INV-001 | Cross-View Invariants | Evaluating script text through `Engine::eval_with_scope`, evaluating an `AST` through `Engine::eval_ast_with_scope`, and evaluating an equivalent Grain `Program` through `Vm::eval_with_scope` must produce the same public success value or public error variant family for the same engine and starting scope. |
| RHAI-INV-002 | Cross-View Invariants | A variable changed by script execution must be visible through `Scope::get_value`, `Scope::get`, `Scope::iter`, and later evaluations using the same `Scope`. |
| RHAI-INV-003 | Cross-View Invariants | A constant inserted through `Scope::push_constant` or `push_constant_dynamic` must be visible to compilation for constant propagation and must reject runtime assignment through engine, module, and Grain VM execution paths. |
| RHAI-INV-004 | Cross-View Invariants | A native function registered through `Engine::register_fn`, `Engine::register_raw_fn`, `Module::set_native_fn`, or a global module must resolve consistently from script text, compiled `AST` calls, `Engine::eval_fn_call`, and Grain VM execution when the function is in scope. |
| RHAI-INV-005 | Cross-View Invariants | A module registered through `StaticModuleResolver`, `register_static_module`, or a self-contained `AST` must expose the same public variables and functions through namespace-qualified script access and module inspection APIs. |
| RHAI-INV-006 | Cross-View Invariants | A custom type display name registered on an engine or module must be used consistently by `type_of`, mismatch errors, native call resolution, and metadata/signature projections where those projections are enabled. |
| RHAI-INV-007 | Cross-View Invariants | A Grain `Program` written with `write` and read with `Program::read` must evaluate with the same result, scope mutations, function-pointer capability, and public error semantics as the original program in the same engine environment. |
| RHAI-INV-008 | Cross-View Invariants | When positions are stripped from a Grain artifact, VM runtime errors must omit direct script positions while `fault_trace` and the retained `Sidecar` must resolve instruction addresses back to source sites. |
