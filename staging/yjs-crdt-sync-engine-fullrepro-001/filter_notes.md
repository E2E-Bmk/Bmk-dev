decision: keep
reason: a CRDT synchronization engine is the hardest class of state engine in the TS ecosystem: one operation store with seven public projections, and the discriminating tests are equivalence-grade cross-doc properties (same update set in any order/grouping -> identical Map/Array/Text views, undo stacks that respect remote origins, positions that survive concurrent prepends). 22.7k stars, 8.2M weekly downloads.
risks: (1) upstream tests non-portable (lib0/testing runner + relative src imports + fuzz helpers) -> generated_only oracle, every expected value observed by executing 13.6.32;
  (2) clientIDs are random so concurrent-conflict winners are nondeterministic per run -> assert convergence (both docs equal, winner is one of the written values), never a specific winner;
  (3) event.changes/.delta must be read inside the observer callback (computing them later throws) -> tests capture projections synchronously inside handlers;
  (4) prelim types read before integration warn and return empty -> assert reads only after integration except where the spec states the prelim contract;
  (5) exact binary layout of updates/state vectors is implementation detail -> assert only round-trip/algebraic properties (apply(encode(doc)) reproduces content, sv-bounded diffs replay), plus Uint8Array typing;
  (6) doc.toJSON materialization quirk (root types appear only after typed accessor calls) -> scope doc-level JSON out, assert type-level toJSON only
