# Clause Sidecar — cargo-generate-fullrepro-001

Each clause ID maps to a verbatim candidate-visible sentence and section anchor.

| Clause ID | Section | Clause |
|---|---|---|
| CG-SRC-001 | Template Source Selection | The `Cli` enum must parse the `cargo generate` subcommand and its visible alias `cargo gen` into a `GenerateArgs` value. |
| CG-SRC-002 | Template Source Selection | The `generate` function must accept a `GenerateArgs` value and return the final generated `PathBuf` when generation succeeds. |
| CG-SRC-003 | Template Source Selection | When the `--path` option is present, the generator must copy a local directory template and must reject simultaneous `--git`. |
| CG-SRC-004 | Template Source Selection | When the `--git` option is present, the generator must treat even a local path as a git source so branch, tag, revision, identity, gitconfig, and submodule options apply to the clone path. |
| CG-SRC-005 | Template Source Selection | When no explicit source option is present, `auto_path` must classify input in this order: configured favorite, host-prefixed shorthand, full URL or scp-style URL, absolute path, existing local relative directory, unprefixed `owner/repo` shorthand, and finally a raw git URL string. |
| CG-SRC-006 | Template Source Selection | When a template input starts with `gh:`, `gl:`, `bb:`, or `sr:`, the generator must expand it respectively to the GitHub, GitLab, Bitbucket, or SourceHut HTTPS URL form documented for the prefix. |
| CG-SRC-007 | Template Source Selection | When an unprefixed `owner/repo` input has exactly one slash and both parts contain only ASCII letters, digits, underscore, dash, or dot, the generator must expand it as a GitHub repository unless an existing local directory with that relative path exists. |
| CG-SRC-008 | Template Source Selection | When the input is a full URL or scp-style `user@host:path`, the generator must use it as a git source without applying host shorthand expansion. |
| CG-SRC-009 | Template Source Selection | Where a subfolder is selected, the generator must search for `cargo-generate.toml` in the selected folder and then upward toward the template root. |
| CG-VAL-001 | Project Naming, Values, And Config | The generator must obtain `project-name` from the `name` field, from interactive input, from `CARGO_GENERATE_VALUE_PROJECT_NAME` in silent operation, or from an init hook that sets it before prompting. |
| CG-VAL-002 | Project Naming, Values, And Config | When force is disabled, `project-name` must be converted to kebab case for the output directory and `crate_name` must be the snake case form. |
| CG-VAL-003 | Project Naming, Values, And Config | The template object must include `authors`, `project-name`, `crate_name`, `crate_type`, `os-arch`, `username`, `within_cargo_project`, and `is_init`. |
| CG-VAL-004 | Project Naming, Values, And Config | Where `cargo-generate.toml` contains a `[placeholders]` table, each placeholder definition must accept `prompt`, optional `choices`, optional `default`, optional string regex validation, and a `type` of `"string"`, `"text"`, `"editor"`, `"bool"`, or `"array"`. |
| CG-VAL-005 | Project Naming, Values, And Config | When a value is missing, silent mode is enabled, and the placeholder has a default value, the generator must use the default value instead of prompting. |
| CG-VAL-006 | Project Naming, Values, And Config | Template values must be merged in increasing priority from global config `[values]`, selected favorite `[favorites.<name>.values]`, environment file values from `CARGO_GENERATE_TEMPLATE_VALUES_FILE`, `CARGO_GENERATE_VALUE_<KEY>` environment variables, the `template_values_file` argument, and the `define` argument. |
| CG-VAL-007 | Project Naming, Values, And Config | `app_config_path` must return an explicit config path when one is supplied, otherwise it must use `$CARGO_HOME/cargo-generate.toml` when present, then `$CARGO_HOME/cargo-generate` when present, and otherwise the preferred `$CARGO_HOME/cargo-generate.toml` path. |
| CG-VAL-008 | Project Naming, Values, And Config | `list_favorites` must load the selected config, filter favorite names by the optional `auto_path` prefix, sort matching names lexicographically, and return success for both empty and non-empty favorite lists. |
| CG-VAL-009 | Project Naming, Values, And Config | Where a library caller uses `GenerateArgs::default`, `crate_type` must default to `"lib"` unless `bin` is selected; where the CLI is invoked without either crate-type flag, `crate_type` must default to `"bin"`. |
| CG-VAL-010 | Project Naming, Values, And Config | When a value is missing, silent mode is enabled, and the placeholder has no default value, the generator must raise an error instead of prompting. |
| CG-VAL-011 | Project Naming, Values, And Config | If a placeholder definition uses the reserved names `project-name`, `crate_name`, `crate_type`, `authors`, `os-arch`, `within_cargo_project`, or `is_init`, then generation must raise an error. |
| CG-REN-001 | Rendering, File Selection, And Template Configuration | The generator must process Liquid syntax in file contents selected for rendering and in file or directory names. |
| CG-REN-002 | Rendering, File Selection, And Template Configuration | It must support standard Liquid tags and filters plus the documented filters `rhai`, `kebab_case`, `lower_camel_case`, `pascal_case`, `shouty_kebab_case`, `shouty_snake_case`, `snake_case`, `title_case`, and `upper_camel_case`. |
| CG-REN-003 | Rendering, File Selection, And Template Configuration | Where `[template].include` is present, only paths matching the include list must be processed for Liquid content rendering. |
| CG-REN-004 | Rendering, File Selection, And Template Configuration | Where include is absent and `[template].exclude` is present, paths matching the exclude list must be copied without Liquid content rendering. |
| CG-REN-005 | Rendering, File Selection, And Template Configuration | Where both include and exclude are present, include must take precedence. |
| CG-REN-006 | Rendering, File Selection, And Template Configuration | Where `[template].ignore` is present, matching files or directories must be removed from the generated template before final copy and must not appear in the output directory. |
| CG-REN-007 | Rendering, File Selection, And Template Configuration | Ignore matching must be evaluated after `.liquid` suffix removal, so an ignore entry for `file.txt` must remove a template file named `file.txt.liquid` from the output. |
| CG-REN-008 | Rendering, File Selection, And Template Configuration | A template file ending in `.liquid` must be copied without that suffix. |
| CG-REN-009 | Rendering, File Selection, And Template Configuration | When both `name` and `name.liquid` exist in the same source folder, the `.liquid` file must take precedence over the non-liquid file for the output path. |
| CG-REN-010 | Rendering, File Selection, And Template Configuration | Where `[template].vcs` is present, it must set the effective VCS for generation even when the caller supplies a VCS option. |
| CG-HOOK-001 | Conditionals And Hooks | Where `cargo-generate.toml` contains `[conditional.'<expr>']` tables, the condition string must be evaluated as a Rhai expression against the values resolved before conditional processing. |
| CG-HOOK-002 | Conditionals And Hooks | For each true condition, the table's `include`, `exclude`, `ignore`, and `placeholders` entries must contribute to the effective template configuration. |
| CG-HOOK-003 | Conditionals And Hooks | The generator must resolve placeholders declared in the non-conditional `[placeholders]` table before evaluating conditional sections. |
| CG-HOOK-004 | Conditionals And Hooks | Where `[hooks]` declares `init`, `pre`, or `post` script lists, the generator must execute init hooks before prompting for normal placeholder values, pre hooks after configured placeholders have been resolved and before template content rendering, and post hooks after template expansion but before final output is moved into the destination. |
| CG-HOOK-005 | Conditionals And Hooks | Hook scripts must access template variables through `variable::is_set`, `variable::get`, and `variable::set`. |
| CG-HOOK-006 | Conditionals And Hooks | Hook scripts must access template-folder files through `file::exists`, `file::rename`, `file::delete`, `file::write`, and `file::listdir`. |
| CG-HOOK-007 | Conditionals And Hooks | The `system::command` function must execute a command only after interactive approval or when `allow_commands` is true, and silent mode without command authorization must raise an error. |
| CG-OUT-001 | Output Git, Test, And Workspace State | When init mode is false, generation must create or reuse a subdirectory under `destination` named from the effective project name. |
| CG-OUT-002 | Output Git, Test, And Workspace State | When init mode is true, generation must write directly into `destination` and must not create a project-name subdirectory. |
| CG-OUT-003 | Output Git, Test, And Workspace State | The `Vcs` enum must accept `Git` and `None`, and parsing must reject any other VCS value. |
| CG-OUT-004 | Output Git, Test, And Workspace State | When no caller, favorite, or template configuration selects a VCS, the effective VCS must be `Git`. |
| CG-OUT-005 | Output Git, Test, And Workspace State | Unless no-workspace is true, the generator must search parent directories for a Cargo workspace and add the generated project as a workspace member when a workspace is found. |
| CG-OUT-006 | Output Git, Test, And Workspace State | When test mode is true, the generator must expand the selected template in a temporary processing directory and run the configured test command there instead of copying the result into the destination. |
| CG-OUT-007 | Output Git, Test, And Workspace State | The default test command must be `cargo test`, and the `CARGO_GENERATE_TEST_CMD` environment variable must replace that command when it is set. |
| CG-OUT-008 | Output Git, Test, And Workspace State | When effective VCS is `Git`, init mode is false, and the project is not added as a workspace member, the generator must initialize a new git repository in the output project. |
| CG-OUT-009 | Output Git, Test, And Workspace State | Test mode must enable verbose output. |
| CG-OUT-010 | Output Git, Test, And Workspace State | When test mode is true and no template source input is supplied, the generator must use the current directory as the template source. |
| CG-OUT-011 | Output Git, Test, And Workspace State | When test mode is true and no project name is supplied, the generator must synthesize a project name before expansion. |
| CG-ERR-001 | Error Semantics | If writing to the formatter fails, then the function must return the I/O error. |
| CG-INV-001 | Cross-View Invariants | A project name supplied through CLI arguments, values files, environment values, interactive input, or init hooks must produce consistent `project-name`, `crate_name`, destination path, rendered path names, and rendered file contents. |
| CG-INV-002 | Cross-View Invariants | A value selected through config defaults, favorite values, environment values, values files, or `define` must be the same value visible to Liquid templates, Rhai conditionals, Rhai hook `variable::get`, and final generated files. |
| CG-INV-003 | Cross-View Invariants | A file ignored through `[template].ignore`, deprecated `.genignore`, or a true conditional ignore entry must be absent from the final filesystem tree and must not be rendered, copied, or committed by git initialization. |
| CG-INV-004 | Cross-View Invariants | A file excluded from Liquid processing must still be copied to the final output unless it is ignored, and that copied content must remain unrendered while rendered file and directory names elsewhere still use the template variables. |
| CG-INV-005 | Cross-View Invariants | A hook-created, hook-renamed, or hook-deleted file in the template processing directory must affect the same final output tree returned by `generate` and observed after CLI completion. |
| CG-INV-006 | Cross-View Invariants | A selected favorite must resolve to the same template source, subfolder, values, init behavior, overwrite behavior, and VCS behavior whether generation is invoked by `auto_path`, by the `favorite` field, or by the CLI favorite syntax. |
| CG-INV-007 | Cross-View Invariants | When a generated project is added to a Cargo workspace, the workspace manifest and generated filesystem tree must agree on the relative member path, and normal fresh git initialization must be suppressed unless force-git-init is true. |
| CG-INV-008 | Cross-View Invariants | The path returned by `generate` must be the same directory that contains rendered output files, git metadata when initialized, and workspace membership effects when a parent workspace is updated. |
