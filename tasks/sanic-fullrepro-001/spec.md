# Sanic Public Application Specification

## Product Overview

Sanic is an asynchronous Python web framework centered on an application
object that owns routes, blueprints, configuration, middleware, listeners,
static file declarations, and public request and response helpers. A user
builds an app by registering handlers, composing blueprints, loading config,
and then exercising the result through a public in-process ASGI test client.

The covered behavior is deterministic and local. It uses declared routes,
temporary local files, request payloads, response helpers, and path generation
to compare the same app facts through independent public projections.

## Scope

This package covers:

- `Sanic` app construction and documented route decorators for common methods.
- `Blueprint` and `Blueprint.group` URL prefixes, route names, and `url_for`
  path generation.
- Query-string and anchor path construction, including static file names.
- Request helpers for JSON, raw body bytes, headers, bearer tokens, query
  lists, path parameters, form fields, uploaded files, method flags, and app
  context access.
- Response helpers for text, HTML, JSON, raw bytes, empty responses, redirects,
  file responses, JSON response mutation methods, and cookie jar behavior.
- `Config` and app config loading from environment variables, dictionaries,
  objects, instances, and local Python files, including custom converters and
  detailed converters.
- Deterministic local static directory serving with semantic content and
  content-type checks.
- In-process request and response middleware, blueprint middleware, listener
  hooks, and middleware priority through the public ASGI test client.

## Installable Surface

The package is imported as `sanic` with public submodules `sanic.blueprints`,
`sanic.config`, and `sanic.response`. The tests use `Sanic`, `Blueprint`,
`Config`, `DetailedConverter`, and documented response helper functions. They
do not import private implementation modules or upstream test modules.

## Product State Model

A `Sanic` app stores config values, registered routes, named routes, static
file routes, middleware chains, listener hooks, and app context. A `Blueprint`
stores deferred route and middleware declarations and projects them onto an app
when registered. URL generation maps registered names and path parameters into
stable paths.

Each request has a request object with parsed body, query, header, form, file,
and route facts. Each handler or middleware returns or mutates a public response
object whose status, body, content type, headers, cookies, and JSON payload can
be observed through the ASGI test client.

## Error Semantics

Unsupported HTTP methods return a method-not-allowed response. Missing routes
and failed URL generation raise or project public framework errors, but tests
check exception classes or semantic status fields rather than exact diagnostic
wording. Config loaders keep uppercase settings and ignore lowercase names.
Converters raise `ValueError` to decline a conversion path.

## Cross-View Invariants

The following facts must agree across public projections:

- A path returned by `app.url_for` reaches the same registered handler through
  the ASGI test client.
- Blueprint and grouped-blueprint names produce paths matching their registered
  URL prefixes.
- Config values loaded before request handling are visible from handlers and
  middleware.
- Request body, query, form, file, header, and token facts are reflected in
  response payloads without depending on whole-response snapshots.
- Static paths generated by `url_for` return the deterministic local file
  bytes and semantic content type.
- Middleware and listeners project their order and state changes through public
  response bodies and headers.

## Representative Workflows

```python
from sanic import Sanic
from sanic.blueprints import Blueprint
from sanic.response import json, text

app = Sanic("example")
app.config.USE_UVLOOP = False
app.update_config({"GREETING": "hello"})

bp = Blueprint("api", url_prefix="/api")

@bp.post("/echo/<name>")
async def echo(request, name):
    return json({"name": name, "body": request.json["body"]})

@app.on_response
async def add_header(request, response):
    response.headers["x-greeting"] = request.app.config.GREETING

app.blueprint(bp)
path = app.url_for("api.echo", name="sanic")
```

The same workflow can be checked through the returned path, the handler's JSON
payload, response headers, and loaded config values.

## Non-Goals

This package does not cover live server processes, worker management, private
implementation modules, upstream source tests, external services, network
access, sleeps, timing behavior, host-specific configuration, generated IDs,
exact log text, or full response snapshot matching where semantic fields are
enough.

## Invocation Protocol

Run from the task directory with the fixed source checkout supplied on
`PYTHONPATH`:

```text
PYTHONPATH=<fixed-source-checkout> PYTHONDONTWRITEBYTECODE=1 LC_ALL=C LANG=C TZ=UTC
python -m pytest <public-test-directory> -q -W error --json-report
```

The local JSON report is written below `logs/`. The support environment runs
the two public test files without modifying the source checkout or requiring a
service.

## Environment

The intended environment is Python 3.11 on Linux without network access, and
these tests require no remote service. This is an environment contract; the
local replay does not prove network isolation. The support packages `pytest`,
`pytest-json-report`, `sanic-testing`, `sanic-routing`, `httptools`,
`aiofiles`, `websockets`, `multidict`, `html5tagger`, `tracerite`,
`typing-extensions`, and `setuptools` are installed. The target package is not pre-installed;
the fixed source checkout is supplied as the import surface. A
separate Python 3.10 replay uses the same requirements.

## Evaluation Notes

The atomic layer establishes narrow public contracts for config, routing,
request helpers, response helpers, static serving, middleware, and listeners.
The integration layer composes those contracts into multi-operation workflows
that compare route generation, request handling, config state, response
metadata, local files, and middleware/listener effects through public outputs.
The package records local reproducibility artifacts only and makes no claim
about an external trusted runner or delivery status.
